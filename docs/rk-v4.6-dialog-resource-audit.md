# RK 4.6 dialog-resource inventory and 4.06 comparison

## Scope and method

This report covers only `RT_DIALOG` resources in the extracted 4.6-labeled
package's `app` directory. The package was statically extracted; no RK
executable, installer, or updater was launched. No keyboard interface was
opened and no device command was sent.

The inventory is
[`rk-v4.6-dialog-resource-controls.csv`](rk-v4.6-dialog-resource-controls.csv),
generated by the existing
[`audit_dialog_resources.py`](../scripts/audit_dialog_resources.py) parser.
The parser's optional `--manifest` argument verifies each present PE input's
size and SHA-256 before reading its resources. The four expected 4.6 PE inputs
were checked against the package manifest: `DeviceDriver.exe`
(`8D8538DE3ADA5FCF80E00C13B364B17ACEFA708480E102EC1E6A0B1309639AE9`),
`Dev/01AF/Update.exe`
(`27894463B0DFE5BC3F5DC19D4D3351D9DFB692C402BF277BDE3889D37E4A206C`),
`InitSetup.dll`
(`59DB7BFD9A92CC9A0998260807F17C536EC71159B727DF10D08B998BC94DE301`), and
`uninstall.dll`
(`9CA1EBC49998B8B2971DEBC1776E7AFF6086AEB86ADCCA6CFB95E9FB399EB03C`). The
parser found dialog resources in the first two files; the two helper DLLs
have no `RT_DIALOG` resources. The generated output contains 50 rows, with no
parse errors.

Recreate the inventory from a statically extracted package with:

```powershell
python scripts/audit_dialog_resources.py `
  --rk-root "C:\path\to\extracted\package\app" `
  --manifest docs/rk-4.6-package-manifest.csv `
  --output docs/rk-v4.6-dialog-resource-controls.csv
```

## Results

| Binary | Dialog templates | Control rows | Empty templates | Parse errors |
| --- | ---: | ---: | ---: | ---: |
| `DeviceDriver.exe` | 10 | 7 | 8 | 0 |
| `Dev/01AF/Update.exe` | 4 | 34 | 1 | 0 |
| **Total** | **14** | **41** | **9** | **0** |

The main driver has controls in two generic templates: a two-button `Dialog`
and a five-control `New` dialog. The other eight driver templates contain no
static controls. This does not mean the runtime feature pages are empty; the
4.6 driver constructs most UI elements through MFC and custom controls.

The updater has 34 control rows across three templates, including the 25
controls in resource 102, the four controls in resource 100, and the generic
five-control `New` dialog. One additional template has no controls. Resource
102 includes firmware and device information captions, BLE/HID version fields,
the file chooser, upgrade and BLE-read controls, progress bars, VID/PID fields,
and the dongle-pairing checkbox. The updater binary is byte-identical to the
installed 4.06 updater, so these resource rows are expected to match.

## Comparison with installed 4.06

The parsed `DeviceDriver.exe` dialog/control projection is identical between
the extracted 4.6 driver and installed 4.06 driver across all 15 emitted rows.
The updater projection is also identical across its 35 rows, and the updater
PE hash is byte-identical across packages. The installed 4.06 inventory has
two additional rows from its generated `unins000.exe`; that generated
uninstaller is not present in the statically extracted 4.6 payload. This is a
payload difference, not proof that installing 4.6 would omit an uninstaller.

The matching embedded dialog resources establish only that this part of the
resource surface is the same. The 4.6 `DeviceDriver.exe` itself has a different
hash from 4.06. Matching `RT_DIALOG` templates do not establish matching MFC
message maps, runtime-created controls, callback code, localization lookups,
feature behavior, or model-specific device paths. Those remain separate audits;
see the [coverage index](../COVERAGE.md) and
[4.6 package snapshot](rk-v4.6-package-snapshot.md).
